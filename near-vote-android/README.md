# Near Vote Android

Android Native Kotlin 기반 Nearby Connections PoC 프로젝트입니다.

목표는 웹 프로토타입의 근거리 네트워크 시뮬레이션을 실제 Android 기기간 발견, 연결, 메시지 교환으로 바꾸는 것입니다.

## 현재 범위

- Android 프로젝트 골격
- Nearby Connections 권한 선언
- 런타임 권한 요청
- 광고/탐색 시작 버튼
- 연결 요청/수락
- UTF-8 JSON 텍스트 payload 송수신
- Poll/Vote/Receipt/Result/Gossip 메시지 타입 초안
- 한 기기에서 설문/투표/영수증/결과 블록을 확인하는 로컬 시뮬레이션
- 홈, 설문 작성, 주변 투표, 결과, 개발자 진단 화면 분리
- 질문, 선택지, 제한시간을 직접 입력하는 설문 게시 화면
- 제한시간 종료 시 제안자 기기에서 결과 자동 공유
- 같은 참여자 아이디의 중복 투표 방지
- 형용사+사물 형식의 아이디 제안, 저장, 수정
- 공유된 결과와 내 투표 영수증 로컬 저장
- 기본 템플릿 선택, 내 템플릿 저장/삭제
- 결과 블록의 참여자 목록 포함과 결과 해시 재검증
- 앱 실행 후 자동 Nearby 광고/탐색 시작
- 30초 주기 주변 연결 유지와 접속자 수 표시

## 열기

Android Studio에서 이 폴더를 열고 Gradle sync를 실행합니다.

```text
/Users/neo/Documents/여러가지/near-vote-android
```

Android Studio의 내장 JBR을 사용하면 터미널에서도 Gradle Wrapper로 빌드할 수 있습니다.

```sh
JAVA_HOME="/Applications/Android Studio.app/Contents/jbr/Contents/Home" ./gradlew :app:assembleDebug
```

## 한 기기 테스트

안드로이드 기기가 1대뿐이면 `로컬 시뮬레이션 실행`을 눌러 개발을 이어갑니다.
이 모드는 가상 참여자 3명을 만들고 설문 생성, 투표, 영수증, 결과 블록 로그를 한 번에 보여줍니다.
실제 무선 연결 검증은 아니지만, 두 번째 기기를 확보하기 전까지 앱 흐름과 원장 메시지 구조를 다듬는 데 사용합니다.

## 두 기기 연결 테스트

1. 두 Android 기기에 같은 APK를 설치합니다.
2. 두 기기 모두 Bluetooth, Wi-Fi, 위치를 켭니다.
3. 앱 권한 요청을 모두 허용합니다.
4. 홈의 자동 연결 상태에서 `연결된 기기 1대`가 보이는지 확인합니다.
5. 필요하면 `개발자 진단`에서 `테스트 메시지 보내기`를 누릅니다.
6. 반대쪽 로그에 메시지 수신 기록이 보이면 Nearby 통신이 확인된 것입니다.

## 투표 게시와 참여 테스트

1. 두 기기에서 먼저 `개발자 진단` > `주변 연결 시작`으로 연결합니다.
2. 제안자 기기에서 `설문 만들기`로 질문, 선택지, 제한시간을 입력합니다.
3. 제안자 기기에서 `주변에 게시하기`를 누릅니다.
4. 참여자 기기에 `투표 참여` 화면이 뜨면 선택지를 누릅니다.
5. 참여자 기기에 투표 영수증이 표시되는지 확인합니다.
6. 제안자 기기의 `게시한 투표` 화면에서 집계가 갱신되는지 확인합니다.
7. 같은 참여자가 다시 선택할 수 없는지 확인합니다.
8. 제안자 기기에서 `결과 공유하기`를 누르거나 제한시간 종료 후 결과가 자동 공유되는지 확인합니다.
9. 설문 화면이 늦게 뜨면 제안자 기기에서 `참여 요청 다시 보내기`를 누릅니다.

## 화면 흐름

- 홈: 내 아이디, 새 설문 만들기, 주변 투표 찾기, 로컬 시뮬레이션, 개발자 진단
- 내 아이디: 제안 아이디 사용, 새 아이디 제안, 직접 수정
- 설문 작성: 직접 입력, 템플릿 선택, 템플릿 저장 후 게시
- 주변 투표: 실제 Nearby 탐색으로 이어질 자리
- 시뮬레이션 결과: 참여자, 선택지, 결과, 영수증/해시 요약
- 지난 결과: 저장된 결과 블록, 참여자 목록, 검증 상태, 내 투표 영수증 확인
- 개발자 진단: 광고, 탐색, PING, 상세 로그

홈과 주요 화면은 사용자 행동 중심 카드로 구성하고, Nearby 광고/탐색/PING 같은 개발용 기능은 개발자 진단 화면에만 둡니다.

## 코드 구조

- `MainActivity.kt`: 화면 구성과 사용자 흐름
- `data/NearVoteModels.kt`: 설문, 영수증, 결과 모델과 JSON 변환
- `data/NearVoteStore.kt`: 아이디, 영수증, 지난 결과 로컬 저장
- `nearby/NearbyVoteConnectionManager.kt`: Nearby Connections 광고, 탐색, 메시지 송수신
- `protocol/NearVoteMessage.kt`: 네트워크 메시지 envelope
